# 문제 정의 솔루션(모호한 문제 구조화하기)

> 중학교 3학년 정보 수업 시간에 문제해결과 프로그래밍 단원을 가르칠 때 문제 분석(문제 이해, 핵심 요소 추출 등) 과정을 제대로 가르치고 싶다. 엔트리로 코드를 한줄씩 만드는 과정도 중요하지만 앞으로는 문제를 정의하고 설계하는 과정이 더 중요해지고 있는 만큼 학생들이 모호하게 정의한 문제 상태(현재상태, 목표상태)에 대해 피드백을 주고 제대로 정의할 수 있도록 하고싶다.

## 써 보기

- 배포: https://problem-definition-solution.vercel.app/
- 저장소: https://github.com/jjieunedu/problem-definition-solution

## 어떤 문제를 풀었나

정보 교과서의 추상화(문제이해, 핵심요소 추출) 단원 내용이 실질적으로 학생들이 문제의 핵심을 파악하고 구조화하는 데 도움이 되었으면 좋겠다.

## 무엇이 되면 성공인가

학생들이 문제를 작성하면 모호한 표현에 대한 피드백을 주고 교정하여 본인이 해결하고 싶은 문제와 원하는 결과를 정확히 정의하도록 한다.

## 사용자가 겪는 흐름

[화면1] 문제 분해 대시보드

학생이 본인이 해결하고 싶은 문제를 아래 3가지 항목으로 나누어 작성한다. 각 항목은 20자 이상 입력해야 한다.

현재 상태: 지금 무엇이 문제인지, 왜 불편/부족한지
목표 상태: 해결 후 어떤 상태가 되길 원하는지
필요한 조건(제약사항): 시간, 자원, 규칙 등 지켜야 할 조건

→ 작성 후 「피드백 받기」 버튼을 클릭하면 사전에 정의된 모호 표현(예: "그냥", "좋게", "잘", "많이", "적당히")이나 대상·기준이 불명확한 표현을 찾아 빨간색 밑줄/하이라이트 + 구체적인 피드백 문구를 제공한다.
→ 논리적 정합성(목표와 현재 상태의 모순 등)은 MVP에서 자동 판별하지 않는다.
→ 학생은 피드백을 참고해 문장을 수정한다.
→ 3개 항목 모두 20자 이상 + 주요 모호 표현 없음을 만족하면 「다음」 버튼이 활성화되어 화면2로 이동한다.
→ 20자를 채우기 위해 같은 글자를 반복하거나 의미 없는 내용을 입력한 경우에는 통과시키지 않고「문제의 구체적인 내용을 작성해주세요」라는 안내를 제공한다.
→ AI 피드백 기능을 사용할 경우 응답 지연이나 오류가 발생하면「피드백을 불러오지 못했습니다. 잠시 후 다시 시도해주세요」를 표시하고 학생이 직접 내용을 수정하거나 다시 요청할 수 있도록 한다.
→ 문제 작성 시 이름, 연락처, 친구·교사 등의 개인을 식별할 수 있는 정보는 입력하지 않도록 안내한다.

[화면2] 핵심 요소 태깅

화면1에서 작성한 3개 항목의 글이 각각 카드 형태로 제시된다.
학생은 문장 속에서 핵심 키워드(단어/구)를 드래그하여 선택한 후 태그 버튼을 클릭해 현재상태 / 목표상태 / 제약 / 이해관계자 / 성공기준 중 하나로 지정한다.

→ 선택한 텍스트는 「선택한 내용: 학교 급식 잔반」과 같이 별도로 표시하여 어떤 텍스트에 태그가 적용되는지 명확하게 보여준다.
→ 태깅이 어렵거나 시작하지 못하는 학생을 위해 힌트 버튼, 예시 태깅 1개 미리보기 등의 스캐폴딩을 제공한다.
→ 최소 1개 이상 태깅을 완료하면 「다음」 버튼이 활성화되어 화면3으로 이동한다.

[화면3] 구조화된 문제 정의 결과

학생이 입력한 3가지 항목과 태깅한 핵심 요소를 구조화된 카드/표 형태로 보여준다.
「AI 프롬프트로 복사」 버튼을 누르면 구조화된 결과가 프롬프트 형식의 텍스트로 변환되어 클립보드에 복사된다.

→ 「AI에 입력하기 전에 개인정보가 포함되어 있지 않은지 확인하세요」라는 안내를 제공한다.
→ 「다시 수정하기」 버튼을 누르면 화면1로 돌아가 작성 내용을 수정할 수 있다.

## 어떻게 만들었나

- 스택: HTML 단일 파일+Netlify
- 테스트: 실패 2개로 시작해 12개를 통과시켰습니다
- 기획과 구현, 검토를 클로드와 했고 검토는 새 대화에서 받았습니다

정상 케이스

정상 1. 모호 표현 피드백 제공
학생이 3개 항목에 문제 상황을 입력한다.
그냥, 잘, 좋게, 많이 등 사전에 정의된 모호 표현이 발견되면 해당 부분을 하이라이트하고 구체적인 수정 피드백을 제공해야 한다.

정상 2. 구조화된 문제 정의 결과 생성
학생이 3개 항목을 조건에 맞게 작성하고 핵심 요소를 1개 이상 태깅한다.
화면3에서 3개 항목과 핵심 태그가 구조화되어 표시되고, 「AI 프롬프트로 복사」를 통해 결과를 텍스트로 복사할 수 있어야 한다.

실패/예외 케이스

실패 1. 20자 미만 또는 의미 없는 반복 입력
학생이 20자 미만으로 입력하거나 같은 문자·단어를 반복하여 글자 수만 채운다.
20자 이상 작성하라는 안내 또는 구체적인 문제 내용을 작성하라는 안내가 표시되고 「다음」 버튼은 활성화되지 않아야 한다.

실패 2. 태깅을 어려워하는 경우
학생이 핵심 요소를 선택하지 못하거나 태깅을 시작하지 않는다.
「힌트」와 「예시 태깅 보기」를 제공하고, 텍스트를 선택한 뒤 태그를 지정했을 때 선택한 텍스트와 태그의 연결 관계가 명확하게 표시되어야 한다.

실패 3. AI 피드백 호출 실패
학생이 「피드백 받기」를 클릭했지만 AI 응답 지연, 오류 또는 빈 응답이 발생한다.
오류 메시지와 「다시 시도」 기능을 제공하고, 학생이 작성한 내용이 사라지거나 화면 진행이 막히지 않아야 한다.

실패 4. 개인정보 포함 가능성
학생이 문제 내용에 자신의 이름이나 친구·교사의 이름 등 개인을 식별할 수 있는 정보를 입력한다.
화면3에서 개인정보 입력 주의 안내를 제공하고, AI 프롬프트 복사 전에 개인정보를 확인하라는 경고를 표시해야 한다.

## 검토에서 정한 것

받아들인 것

1. 반나절(약 3시간)에 불가능해 보이는 지점 1가지와 축소안
AI가 5개 항목의 모호성뿐 아니라 논리적 정합성까지 자동 판별하고 빨간색 밑줄·구체적 피드백까지 제공하는 부분이 가장 불가능에 가깝다. 축소해서 오늘은 그냥/잘/좋게/많이/적당히 같은 사전 정의된 모호 표현 탐지 + 20자 검증만 구현하고, 논리적 정합성 검사는 제외하는 것이 안전하다.
2. 테스트 케이스 설계에서 빠진 실패 시나리오 2가지
첫째, 20자는 넘지만 모호 표현만 반복하거나 의미 없는 글자를 채운 경우를 검증해야 한다. 둘째, AI 피드백 요청 실패·응답 지연·빈 응답 등 AI 호출 자체가 실패하는 경우에 학생이 화면에서 막히지 않는지 테스트해야 한다.
3. 와이어프레임과 시나리오가 어긋나는 부분 1가지
화면2 시나리오는 드래그 또는 클릭으로 단어/구를 선택해 태깅한다고 되어 있지만, 와이어프레임에는 선택된 텍스트와 태그를 실제로 연결하는 UI가 없다. 특히 태그를 클릭한 뒤 어떤 텍스트에 적용되는지 표현이 없어 구현 방식과 사용자 행동이 불명확하다.
4. 학생 개인정보·안전 위험 1가지
화면3의 「AI 프롬프트로 복사하기」를 통해 학생이 작성한 문제 내용에 이름·친구·교사 등 개인식별정보가 포함된 채 외부 AI에 전송될 가능성이 있다. 최소한 개인정보가 포함될 수 있음을 경고하고, 이름·연락처 등 식별정보를 입력하지 않도록 안내해야 한다.
